# session: entrants, participant selection, weekend start, garages

Owner: see `subsystems.tsv`. Write-up: research/grid24-cap.md §2–3. Goal: 24-car (later 26-car) grids.

## Map: how a Grand Prix gets its cars {#participants}
1. GP mode row → game setup mode `f1_26` → entrant setup mode row 8 (`entrants.entrant_setup_modes.entrant_setup_mode_8`), parsed by `Sess_Parse_EntrantSetupMode` into `EntrantSetupMode` (0x288; `max_entrants` +0x268 stored at `site_Sess_MaxEntrantsStore`).
2. `Sess_Setup_ChampionshipEntrants` (0x140ba3ad0): `EntrantsManager.setup_mode`, `.selectable_list` = first selectable list.
3. Entrant lists are parsed by `Sess_Parse_EntrantList` (0x142453c40) for `i < row_count` (`gamedb#instancecount`): **the 22-car cap is `entrant_list_34._entrant_instancecount_ = 22`, data, not code**.
4. `Sess_Build_CandidatePool` (0x14245fb70) filters by car class, then `Sess_Select_Entrants` (0x1424a2350): `limit = reuse_entrants ? max_entrants : min(max_entrants, #candidates)` (load at `site_Sess_SelectorLimitLoad`, 0x1424a30a8: rax → limit, [rsp+0x60] = EntrantSetupMode), MT draw, player insert, team prune (`max_teams`), entrant prune.
5. `Sess_Weekend_Start` (cxx `game::championship::Weekend::start`) copies entrants into the session vector; no fixed size.
6. Garages: `Sess_SortGarages_Thunk` → `.data1` body → `Sess_Assign_GarageSlotsByClass` → `Sess_Assign_GarageSlotsByPreference` (one garage per team, slots 0,1,2…).

## Wetness, drying and rain -> grip {#wetness}
Static data flow (engine-re 2026-11-14; lanes game/car/render rows stay at their level, see notes there).
1. **Track wetness is a curve, not a simulation.** `Game_TrackInformationSystem_Update` (0x144795cf0, ws = *`g_Game_WeatherSurfaceState`) sets ws+0x3f0a38 = EvalNow(`weather/track/wet_delta` of the active dataset, ws+0xd48 + tod.active_dataset*0x30) every frame (0x144796092). The TOD data of the weather scenario therefore decides how fast the track gets wet and dries; there is no integrator over rain intensity in this path. Before the update the previous ws+0x3f0a38 goes to the render block +0xa5b7e4 (track shader wetness, render lane).
2. **Local drying = the dry line.** `Game_TrackSurface_UpdateWheelRecords` (0x1437cc9c0) computes the dry-line strength ws+0x3f0a64 with 0x1437cda00: the same wet_delta curve sampled `lookback` minutes ago (EvalAt), banded at 0.33 / 0.66 to grow or wash out the line, and the drying factor ws+0x3f0a4c from ws+0x3f0a38. The update then sets ws+0x3f0a48 = clamp01(ws+0x3f0a64) * ws+0x3f0a6c.
3. **Per-wheel surface wetness.** `Game_TrackInfo_SampleWheelSurface` (0x144792f50) reads the RGBA track-space map ws+0x1018 at the wheel (lap fraction, lateral): wetness = clamp01((1 - clamp01(R/255 * ws+0x3f0a70) * ws+0x3f0a48) * ws+0x3f0a38) * G/255 (R = racing line, G = wet distribution, optionally inverted by ws+0x3f0a7c); puddle = 1 where B > 0 and B/255 <= the puddle curve value ws+0x3f0a54 (curve = water level, B = per-texel threshold; V9440). Stored per car/wheel in records sys + car*0x70 + wheel*0x1c (+0x24..).
4. **Into the car.** `vt_Car_VehicleEnvironment` slot 5 (`Car_Surface_SampleAt` 0x142f478d0) returns the record (out[0] = wetness rec+0x2c); the vehicle update 0x1446dc480 copies it to wheel+0x280 (0x1446dc7a4). Slot 3 (`Car_Env_IsTrackWet` 0x142f47880) = ws+0x3f0a38 > sys+0xfcc.
5. **Tyre water.** `Car_Tyre_Step` (0x1446b5720) moves wheel+0x8c toward wheel+0x280 at +4.0/s (wetting) and -0.5/s (drying) (0x1446b59bf..0x1446b5a15).
6. **Grip.** `Car_Tyre_ComputeGripMultiplier` (0x1446b7390, mask 0x20) multiplies grip by the tyre model's WetnessGrip spline at wheel+0x8c * wheel+0x90 (0x1446b75a1); wheel+0x90 is the `wetness_grip_scale` event modifier (`Game_EventModifier_SetWheelWetnessGripScale` 0x1413a6330, default 1.0). With handling version > 6 `Car_Tyre_GripScale` (0x1446b7240) adds 1 - WetnessDownslopeFactor * clamp01(wheel+0x8c / 0.2).
7. **Rain intensity does not reach grip directly.** Rain intensity (owner+0x318) drives visuals (renderer +0x75ca4, ws+0x3f0a3c) and nothing in steps 1-6 reads it; grip only follows the wet_delta curve, the dry line, the map and the tyre water. FFB wet multipliers (`g_Car_FfbForceWetMultiple` / `FrictionWetMultiple`) follow the fitted compound's wet flag ([[tyre+0xc0]]+0xf8), not the track.
8. **The authored curves (doc: TOD file decode, engine-re 2026-11-14).** All tracks share one weather TOD file: `eaid://environment_package/core_assets/sequence_data/sequence_data.weather.tod` (resource 170 of `environment_package/tracks/common_all_tracks.erp`, type TimeOfDay, fragments 27006 / 9412 / 7 bytes; the front end carries an identical copy). Format: `TODD` v2, `SLST` 19 scenario names (`_master`, `scenario_full_transition`, `weather_<From>-<To>_a` = the names the stitch formats), `TWIN`, `PATH` 920 x {u32 key, u32 djb2(scenario), u32 djb2(parameter), u32}, `DATA` 920 x {u32 packed, f32 t_first, f32 t_last} (packed bits 12..21 = key count, bits 22.. = float count; keys are (t, value) pairs in fragment 1, offsets cumulative in record order; check: the float counts sum to exactly 2353 = fragment 1, and 140 of 143 multi-key records start/end at t_first/t_last). PATH entry i pairs with DATA record i (assumed from the order; consistent with every value below). Times are fractions of the state / transition (0.0417 = 1/24, 0.9583 = 23/24). Values held per weather state (`weather_X-X_a`) and blended linearly over the transition (`weather_X-Y_a`, keys at 0.0417 and 0.9583):
   | state | wet_delta (-> ws+0x3f0a38) | wetness | rainfall/intensity | puddles | absorbtion |
   |---|---|---|---|---|---|
   | Clear, LightCloud, Overcast | 0 | 0 | 0 | 0 | 0 |
   | LightRain | 0.33 | 0.13 | 0.33 | 0 | 0.5 |
   | HeavyRain | 0.66 | 1.0 | 0.66 | 0.8 | 0.5 |
   | Stormy | 0.66 | 1.0 | 0.77 | 0.8 | 0.5 |
   Exceptions: Overcast->LightRain wetness starts at t 0.2384, LightRain->Overcast wetness ends at t 0.7806; HeavyRain<->Stormy keep wet_delta 0.66 (only the rain intensity moves 0.66 <-> 0.77); `scenario_full_transition` (a test scenario) ramps wet_delta 0 / 0.33 / 0.66 at t 0.4 / 0.6 / 0.8. So the track-wetness scalar the physics uses is the weather level itself (0 dry, 0.33 light rain, 0.66 heavy rain or storm), lagging nothing; drying after rain is only the transition ramp plus the dry line and tyre water. Decoder: scratch only (not in the repo); the file was read from the game install read-only.
9. **Constants ws+0x3f0a6c / +0x3f0a70.** Both are written only by the constructor 0x14478ef10 (one qword store of 1.0, 1.0 at 0x14478ff95; whole-exe displacement scan). +0x3f0a6c scales the dry-line strength (update 0x1447960de, dry line 0x1437cdc4a, 0x141fab4d3/0x141fab558); +0x3f0a70 is the gain on the map's racing-line channel R in the per-wheel sampler (0x14479315c). Tuning constants, 1.0 in retail.
Open: the curve loader that turns `DATA` records into runtime curves (type 1 = linear keys, 0/2/4 = constant; sampler 0x14029c560) is not decompiled, so the packing and the PATH/DATA pairing rest on the file's self-consistency; meaning of the TWIN chunk; runtime confirmation of every step (trace test needed).
